# README — Crackme p_2.com

Данная программа представляет собой учебный crackme для DOS, демонстрирующий две классические уязвимости переполнения буфера. При вводе пароля программа сравнивает его с эталоном (`secret`) и выводит `Access granted` только при совпадении. Однако из-за отсутствия контроля длины ввода обе уязвимости позволяют получить `Access granted` даже при неверном пароле.

## Общая информация
- **Правильный пароль:** `secret` (6 символов)
- **Уязвимость:** отсутствие контроля длины ввода в функции `my_gets`
- **Обе уязвимости являются следствием переполнения буфера в стеке**

---

## Уязвимость 1: переполнение флага `is_ok`

### Как это работает
В функции проверки пароля `check_password` локальный буфер занимает 16 байт (от `BP-12h` до `BP-3h`). Сразу за буфером, по адресу `BP-2`, расположена двухбайтовая переменная `is_ok` (флаг успеха). Изначально она равна `0`. Если ввести 17 и более символов, 17-й байт перезапишет младший байт `is_ok`. Поскольку после завершения ввода программа сравнивает пароль с `secret` и, если он не совпадает, оставляет `is_ok` равным `0`, но при переполнении флаг становится ненулевым, и функция возвращает истину. В результате выводится `Access granted` независимо от содержимого пароля.

### Эксплуатация
Достаточно ввести 17 любых символов (например, 17 раз `A`) и нажать Enter. Программа выведет `Access granted`.

**Пример:**
```zsh
...\DOC>p_2.com
Enter password (6 chars): AAAAAAAAAAAAAAAAA
Access granted
```

## Уязвимость 2: перезапись адреса возврата

### Как это работает
При вводе более 22 символов данные выходят за пределы буфера, затирают флаг `is_ok`, сохранённый регистр `BP` и, наконец, **адрес возврата** из функции `check_password`. Подменив адрес возврата на адрес кода, который выводит `Access granted`, программа после завершения функции перейдёт напрямую к выводу приветствия, минуя проверку пароля. При этом флаг `is_ok` можно обнулить, чтобы проверка формально не прошла.

### Эксплуатация
Для успешной атаки необходимо подать на вход 22 байта данных (плюс завершающий Enter `0x0D`), где:
- байты 0–15 (первые 16) — заполнение буфера (любые символы);
- байты 16–17 — два нулевых байта (обнуляют `is_ok`);
- байты 18–19 — любые два байта (перезаписывают сохранённый `bp`, не критично);
- байты 20–21 — адрес перехода в формате little‑endian (младший байт первым);
- байт 22 — `0x0D` (Enter).

В нашем случае адрес инструкции вывода `Access granted` — `0x010E`, поэтому байты 20–21 должны быть `0x0E`, `0x01`.

### Создание бинарного файла
Создайте файл `exploit.bin` с 23 байтами следующего содержания:

```
41 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41 00 00 42 42 0E 01 0D
```
Расшифровка:
- `41` (16 раз) — заполнение буфера;
- `00 00` — обнуление флага;
- `42 42` — заполнение сохранённого `bp`;
- `0E 01` — адрес `0x010E` (little‑endian);
- `0D` — Enter.

**Способ создания на современной ОС (Mac/Linux):**
```bash
printf 'AAAAAAAAAAAAAAAA\x00\x00BB\x0e\x01\x0d' > exploit.bin
```

**Пример:**
```zsh
# нажать esc, чтобы выйти в обычный DOSBOX
...\DOC>p_2.com < exploit.bin
Enter password (6 chars): Access granted
```

При выполнении ret управление передаётся по адресу `0x010E`, где находится код вывода сообщения `Access granted`. Проверка пароля игнорируется.
