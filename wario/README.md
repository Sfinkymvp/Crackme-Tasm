# Анализ защищённой программы (результат дизассемблирования)

## О работе

Данный документ описывает процесс взлома (crack) бинарного файла, который был предоставлен мне моим одногруппником Александром. С помощью дизассемблера я исследовал внутреннюю структуру программы, выявил две уязвимости, связанные с переполнением буфера, и разработал способы их эксплуатации для получения несанкционированного доступа. Результаты анализа представлены ниже.

## Общее описание

Исследуемый исполняемый файл представляет собой COM-программу для DOS. При запуске она выводит приглашение `Enter password:`, считывает введённую строку, сравнивает её с эталонным паролем, хранящимся в коде, и в зависимости от результата выводит `Access granted` или `Access denied`. В ходе дизассемблирования обнаружены две критические уязвимости, связанные с отсутствием контроля длины вводимых данных, что приводит к переполнению буфера.

## Структура данных в памяти (после дизассемблирования)

В сегменте данных программы после кода располагаются следующие элементы (адреса указаны относительно начала сегмента с данными в коде seg0000:018E):

| Смещение | Размер | Назначение |
|----------|--------|------------|
| ...      | 16 байт| Буфер для ввода пароля |
| +16      | 1 байт  | Флаг успешной проверки (изначально 0) |
| +17      | 12 байт | Эталонная строка пароля (завершается символом '$') |
| +29      | 1 байт  | Длина эталонного пароля (без учёта '$') |
| +30      | ...     | Строки сообщений и т.д. |

Программа считывает символы до нажатия Enter, записывает их в буфер, после чего помещает символ `$` (ASCII 0x24) сразу за последним введённым символом. Затем вызывается подпрограмма сравнения, которая сравнивает `password_len` байт из буфера с эталонной строкой. Если они совпадают, флаг устанавливается в 1, иначе остаётся прежним. Далее анализируется значение флага: ненулевое - доступ разрешён.

## Уязвимость 1: Перезапись флага через завершающий `$`

### Суть
Так как после буфера (16 байт) непосредственно расположен байт флага, при вводе ровно 16 символов и нажатии Enter программа запишет символ `$` по смещению `буфер + 16`, т.е. прямо в байт флага. Значение `$` = 0x24 (не ноль). После этого:

- Введённые данные (16 символов) не совпадают с эталоном, поэтому флаг не изменяется подпрограммой проверки (остаётся 0x24).
- При проверке флага основная программа видит ненулевое значение и выводит `Access granted`.

Таким образом, любой ввод длиной ровно 16 символов (например, 16 букв `a`) приводит к обходу проверки пароля.

### Демонстрация

```zsh
Enter password: aaaaaaaaaaaaaaaa
Access granted
```

## Уязвимость 2: Перезапись эталонного пароля

### Суть
При вводе более 16 символов переполнение буфера захватывает сначала флаг (смещение +16), а затем область эталонного пароля (начиная со смещения +17). Если ввести достаточно длинную строку, можно полностью или частично изменить эталонный пароль. Поскольку сравнение происходит по длине исходного эталона (например, 11 байт), достаточно перезаписать первые 11 байт эталона такими же символами, как и в начале введённой строки. Тогда сравнение даст положительный результат, и флаг будет установлен в 1.

Например, ввод следующей бинарной последовательности:
```
41 41 41 41 41 41 41 41 41 41 41 24 00 00 00 00 00 41 41 41 41 41 41 41 41 41 41 41 0D
```
- 11 символов `A` - ввод
- символ `$` - конец строки
- 4 нулевых байта - дозаполняем буфер
- нулевой байт - перезаписываем флаг на `0` чтобы не вызвать 1 уязвимость
- 11 символов `A` - перезаписываем корректный пароль
- последний символ - `Enter`

   \*последний символ пароля `$` можно не менять


После этого:
- Эталонная строка теперь начинается с 11 символов `A`.
- Подпрограмма сравнения сравнивает первые 11 байт буфера (это символы `A`) с первыми 11 байтами эталонной строки (тоже `A`). Совпадение.
- Флаг устанавливается в 1.
- Доступ разрешён.

### Демонстрация

```zsh
crackme.com<exploit.bin
Enter password:Access granted
```

## Заключение

Обе уязвимости являются следствием отсутствия проверки длины ввода. Первая позволяет подменить флаг успешной аутентификации, вторая – изменить сам эталонный пароль, сделав его идентичным введённым данным. Для защиты необходимо ограничить количество считываемых символов размером буфера и корректно обрабатывать граничные условия.


# Бинарный патчер для замены пароля

Для демонстрации или изменения поведения программы был разработан патчер, который заменяет исходный пароль `funny_aboba` на другой (11 символов `b`) непосредственно в .com файле.

## Принцип работы

Как работает патчер:
В коде патчера задаётся найденное смещение смещение в байтах, где начинается строка пароля. Патчер просто запишет новые 11 байт по этому смещению.

## Использование

Скрипт написан на Python 3 и не требует дополнительных библиотек.
Скрипт требует смещение в байтах для перезаписи, а также путь до директории, где лежат `.com` файлы

```bash
python3 script.py <output.com>
```
